# 赛博命理项目审查结论与整改方案

> 审查基线：2026-07-21 代码状态  
> 范围：产品方案、八字/紫微/六爻规则、计算引擎、解读质量、前后端、安全、GitHub 治理与部署。

## 1. 执行摘要

项目已经完成三术数主流程、模板/LLM 解读、本地与云端存储、账号、分享和导出。审查基线为：56 个测试文件、444 个测试通过，生产构建成功，ESLint 有 8 个 warning。

当前适合作为传统文化学习型 Alpha 产品，不应在完成 P0 整改前宣传为“权威级专业预测系统”。工程意义上的准确性应满足：

1. 同流派、同策略、同输入得到稳定且可复核的排盘结果；
2. 每条推断可追溯到结构化规则、版本与资料来源；
3. 边界输入、流派差异和信息缺失有明确警告；
4. LLM 不参与排盘，不修改计算事实，不虚构典籍依据。

## 2. 主要发现

### 2.1 P0：上线前必须处理

- Magic Link 在生产邮件发送失败时仍可能返回有效登录链接，存在账号接管风险。
- Magic Link 消费不是原子操作，并发请求可能重复成功。
- 账号删除确认可被省略，云端删除异常会被吞掉，可能出现“返回成功但数据未删净”。
- API 对客户端命盘只做最小字段校验，云端保存、分享和 LLM 解读可能接收伪造派生结果。
- 登录、Magic Link、账号删除和多数 CRUD API 缺少统一请求体上限、Schema 校验和限流。
- 限流直接信任 `x-forwarded-for`；日志可能记录未脱敏客户端 IP。
- 生产未配置 Postgres 时可回落 JSON 文件，不适合并发、多实例或无持久磁盘环境。
- 应用请求期间执行建表 DDL，不符合可控迁移和最小权限原则。
- 仓库尚无正式 Git commit，原项目缺少 CI、CODEOWNERS、SECURITY、Dockerfile 和 Compose。

### 2.2 八字专业性

- 旺衰分析使用以天干字符为键的 `tenGods` 统计力量，相同天干重复出现时会被合并。
- 固定藏干权重适合五行可视化，不能替代月令司令、透干、通根、远近和刑冲合化判断。
- 调候、格局、扶抑、通关、病药被压缩为单一“喜用五行”，缺少冲突解释。
- 起运虽保存年/月细节，但正式大运仍按整岁和整数年份判断。
- 真太阳时未完整建模出生地时区、历史夏令时和行政时间变化。
- 时辰未知仅生成六字盘，没有十二时辰敏感性分析。

### 2.3 紫微专业性

- 当前大限使用 `基准年 - 出生年`，不是严格虚岁，可能造成大限错位一年。
- iztro 未固定为开发依赖；未安装时对照测试仍通过，对照脚本没有真正执行双方 diff。
- 三合盘体、飞星、自化规则同时存在，但缺少流派命名空间和规则优先级。
- 流月、流日属于简化叠盘，需要明确月界、日界和适用流派。
- 未知时辰不应输出唯一完整紫微盘，应进入多时辰校盘。

### 2.4 六爻专业性

- “时间起卦”采用梅花易数先天数，再进入纳甲六爻分析，属于混合方法，应独立标识。
- 已有月建、日辰、旬空和基础应期，但六神、伏神、飞神、月破、暗动、旺相休囚、墓绝、进退和反伏吟尚未完整结构化。
- 用神主要依赖问题关键词，应增加问事类别、主体、性别、关系和用户确认。
- 动变主要描述本爻与化爻五行关系，尚缺回头生克、化进化退、化空化破和冲合转换。

### 2.5 解读与产品可信度

- 典籍标注多为“出处风格”，不等于可核验引用，应建立规则 ID、采用版本、章节和摘要。
- LLM 返回依赖文本分段解析，应改为结构化输出和 Schema 校验。
- “历史事件校准”只追加侧重文案，没有重新计算格局或用神，容易形成确认偏误。
- 专业模式应显示流派、引擎版本、历法策略、证据、边界警告和置信度。

### 2.6 前后端与工程

- 根布局读取会话，使首页和公开分享页等全部成为动态渲染页面。
- 三个新建向导在客户端直接加载完整计算引擎，初始 JS 仍有优化空间。
- API、账号、Postgres/Redis 和主要页面缺少集成/E2E 测试。
- 缺少 CSP、安全响应头、`server-only` 边界和生产配置启动校验。

## 3. 统一整改原则

### 3.1 三层模型

1. **事实层**：历法、干支、星曜、爻位、运限等确定性计算；
2. **规则层**：旺衰、格局、四化、用神、动变等结构化推断；
3. **叙事层**：模板或 LLM 只组织语言，不产生或修改事实。

### 3.2 统一引擎信封

三术数后续统一增加：

- `schemaVersion`：数据结构版本；
- `engineVersion`：计算引擎版本；
- `ruleSetVersion`：规则集版本；
- `school`：采用流派；
- `calendarPolicy`、`timePolicy`、`agePolicy`：历法政策；
- `warnings`：边界、缺失与冲突；
- `evidence`：规则 ID、条件、来源、结论与置信度；
- `inputFingerprint`：用于复算和差异对照的非敏感输入指纹。

### 3.3 产品边界

- 坚持传统文化学习与娱乐定位，不承诺现实预测的科学准确率；
- 优先做到单一流派明确、规则可复核，不优先追求多流派混合；
- 高风险主题必须给出现实建议和专业机构提示；
- 信息不完整或处于边界时，输出候选结果和差异，不输出伪确定结论。
