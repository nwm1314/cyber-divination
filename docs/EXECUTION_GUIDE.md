# 整改任务执行指南

> 对应任务卡：`docs/REMEDIATION_TASKS.md`  
> 状态日期：2026-07-21

## 1. 执行顺序

### Gate A：仓库基线

1. T250 GitHub 项目治理；
2. T251 CI、CODEOWNERS 与质量门禁；
3. 创建基线提交并保护默认分支。

### Gate B：生产安全

1. T252 认证和账号删除安全；
2. T253 API Schema、授权和服务端权威计算；
3. 安全回归通过后才允许继续生产部署。

### Gate C：三术数核心正确性

可并行执行，但写集必须互斥：

- 八字：T260 → T261 → T262；
- 紫微：T270 → T271；
- 六爻：T280 → T281 → T282。

### Gate D：解读与产品

1. T290 结构化解读和证据层；
2. T291 经历反馈机制重构；
3. T292 产品可信度和专业模式。

### Gate E：Docker 与生产放量

1. T300 Standalone Docker；
2. T301 Compose 集成环境；
3. T302 数据库迁移和健康检查；
4. T303 反向代理、备份和发布 QA。

## 2. 任务状态

- `todo`：尚未开始；
- `in-progress`：已有负责人和工作分支；
- `blocked`：存在外部依赖或决策阻塞；
- `review`：代码完成，等待领域或安全审查；
- `done`：DoD、测试、文档和验收全部完成；
- `cancelled`：明确取消并记录原因。

## 3. 分支与 PR

- 默认分支：`main`；
- 工作分支：`codex/t<任务号>-<简短主题>`；
- 一个 PR 原则上只完成一张任务卡；
- 引擎规则、认证、数据库和 CI 文件必须获得 CODEOWNERS 审查；
- PR 必须包含任务号、风险、测试和回滚方式。

## 4. Definition of Ready

任务进入 `in-progress` 前必须具备：

- 明确输入、输出和不做事项；
- 前置依赖已完成或有稳定接口；
- 流派、历法、年龄或安全策略已写入任务卡；
- 验收样例和测试来源明确；
- 数据结构变化已评审迁移与兼容策略。

## 5. Definition of Done

- TypeScript 和 Next.js build 通过；
- ESLint 不新增 warning；
- 新规则和 bug 修复有自动化测试；
- 公共契约变化同步文档和迁移说明；
- 敏感信息不进入日志、快照和 fixture；
- 规则变化更新 `engineVersion` 或 `ruleSetVersion`；
- 生成差异报告并取得领域审校；
- PR 包含回滚方案。

## 6. 测试矩阵

| 层级 | 必须覆盖 |
|---|---|
| 单元测试 | 纯函数、边界、规则表、Schema |
| 金标准 | 外部来源、流派、版本、预期值 |
| API 集成 | 400/401/403/404/409/413/429/500 |
| 数据库 | 迁移、约束、级联、并发、事务 |
| 浏览器 E2E | 新建、解读、登录、同步、分享、删除 |
| Docker | build、非 root、healthcheck、重启、持久化 |
| 安全 | Magic Link、越权、Origin、日志脱敏、超大请求 |

## 7. 发布策略

- Alpha：仅本地或受控测试；
- Beta：完成 W22、W23 和三术数核心正确性任务；
- Production：完成 W28、备份恢复演练和 QA 清单；
- 任一 P0 安全回归失败，立即停止发布并回滚。
