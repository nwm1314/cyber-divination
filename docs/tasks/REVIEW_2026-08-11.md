# Project Review Record — 2026-08-11

## Scope and evidence

This record is a read-only review of product design, source code, test coverage,
operational documentation, and Git history at `main` / `origin/main` commit
`71a9edb`. It is a point-in-time review; code is the source of truth when this
record conflicts with a later revision.

Commands executed during the review:

- `npm test` — 69 test files passed; 546 tests passed; 1 test skipped.
- `npm run build` — Next.js 16.2.10 production build passed.
- `npm run lint -- --max-warnings=8` — exit 0 with 8 warnings.

The skipped test is the optional `iztro` comparison path. Local browser
automation could not produce a trustworthy visual/mobile result because its
loopback runtime was isolated from the locally started application. Mobile
findings below are therefore source-level findings, not a substitute for device
or browser E2E verification.

## Overall conclusion

The application is suitable to continue as a traditional-culture learning and
entertainment Beta. It must not be presented as a professionally authoritative
prediction product or as having completed all of the W22–W28 acceptance
criteria. The deterministic Bazi path has the strongest implementation, but
external validation, server trust boundaries, and documentation truthfulness are
not yet sufficient for those claims.

## Findings

### F-01 — Server authority is incomplete (P0)

`cloudChartUpsertSchema` accepts a minimum client-produced `chart` with
`.passthrough()`. `POST /api/charts` stores the supplied chart/report after
checking only selected fields. The Bazi reading endpoint also validates a
client-produced chart rather than recomputing it from authoritative birth input.
This conflicts with T253's stated requirement that cloud persistence and LLM
reading validate normalized inputs or recompute server-side. A signed-in user
cannot use this to write another user's record, but can persist or narrate
forged derived results in their own record, undermining professional-trust
claims.

Evidence: `src/lib/contracts/charts.ts`, `src/app/api/charts/route.ts`,
`src/app/api/reading/route.ts`, `docs/REMEDIATION_TASKS.md` (T253).

### F-02 — Mutating API protections are not consistently applied (P0)

The shared `parseJsonBody` helper supplies UTF-8 size bounds and Zod parsing,
and the Bazi reading path invokes origin validation. However:

- `PUT /api/people/[id]` calls `request.json()` directly, with no body limit,
  Zod validation, or `assertSameOrigin` check.
- Delete routes for Bazi, Ziwei, and Liuyao cloud records do not use
  `assertSameOrigin`.
- `POST /api/reading/liuyao` and `POST /api/reading/ziwei` do not use
  `assertSameOrigin`.

Cookie `SameSite=Lax` and browser CORS behavior mitigate some cross-site paths,
but they do not justify inconsistent server-side safeguards for protected or
cost-bearing mutations.

Evidence: `src/lib/api/parse-body.ts`, `src/app/api/people/[id]/route.ts`,
`src/app/api/charts/[id]/route.ts`, `src/app/api/ziwei-charts/[id]/route.ts`,
`src/app/api/liuyao-charts/[id]/route.ts`,
`src/app/api/reading/{liuyao,ziwei}/route.ts`.

### F-03 — Rate-limit client identity is forgeable at the application boundary (P1)

`clientKeyFromRequest` accepts the first `X-Forwarded-For` value without a
trusted-proxy boundary. A direct client can rotate this header to bypass an
in-memory or Redis rate-limit key. Deployment documentation instructs operators
to configure a proxy, but the app itself cannot establish that a forwarded
header was injected by one.

Evidence: `src/lib/api/rate-limit.ts`, `docs/DEPLOY.md`.

### F-04 — External validation does not satisfy completed-task claims (P1)

The Bazi source document says the planned >=1,000 external cases are not
complete. `iztro` is not a locked development dependency and
`iztro-compare.test.ts` skips the comparison when absent; this review observed
that skip. Internal golden fixtures are valuable regression tests but are not
independent authority validation.

Evidence: `docs/research/bazi-sources.md`,
`src/lib/ziwei/__fixtures__/iztro-compare.test.ts`,
`scripts/compare-iztro.mjs`, `package.json`,
`docs/REMEDIATION_TASKS.md` (T262/T271).

### F-05 — The Bazi skill is referenced, not fully provenance-controlled (P1)

The engine labels results with `skillRef: "bazi-skill"`; a sync script copies
reference content, and the LLM prompt embeds selected classic-rule snippets.
There is no runtime execution of an external skill, lockfile/version/hash
attestation, or report-level disclosure of which parts of the skill were
adopted, changed, or omitted. Therefore “uses an excellent open-source skill”
cannot currently be treated as an auditable implementation claim.

Evidence: `scripts/sync-bazi-skill.mjs`, `src/lib/bazi/index.ts`,
`src/lib/reading/llm/llm.ts`.

### F-06 — Deterministic rule scope remains incomplete (P1/P2)

Bazi flags true-solar-time limitations, but does not model historical daylight
saving or administrative time-zone changes. The project records remaining Liuyao
state-machine gaps (for example complete seasonal-strength, advance/retreat, and
repetition handling) and incomplete external validation. These must remain
visible product limitations until independently verified, rather than being
hidden behind completed task status.

Evidence: `src/lib/bazi/index.ts`, `docs/research/bazi-sources.md`,
`docs/REMEDIATION_TASKS.md` (known limitations for T260/T281).

### F-07 — Plain-language narrative is improved but still partly generic (P2)

The template provides concrete anchors such as years, ages, visible five-element
percentages, and risk caveats. It also avoids specific-event prediction. Some
recommendations remain broadly reusable (`试点→反馈→加注`, `先挂靠平台`,
`大额决策给自己冷静期`) and do not state the exact chart evidence,
real-world precondition, or non-applicable cases. LLM output has JSON/safety
checks, but the model still creates narrative from a broad system prompt rather
than a per-claim evidence contract.

Evidence: `src/lib/reading/template/plain-copy.ts`,
`src/lib/reading/llm/{llm,parse,safety,evidence}.ts`.

### F-08 — Account/archive lifecycle is clear in places but fragmented (P1)

Server-side ownership checks and exports are generally sound. The product still
uses multiple local/cloud stores and requires users to understand separate
archive, sync, and deletion scopes. Account deletion deliberately does not
delete browser-local data; this is disclosed but does not meet the likely user
expectation of “delete my data” without an explicit local-data action. The
archive page contains stale text saying Ziwei cloud sync is not connected even
though sync functions and login auto-sync exist.

Evidence: `src/components/account/AccountPanel.tsx`,
`src/app/charts/page.tsx`, `src/lib/storage/{mode,sync,migrate}.ts`,
`src/components/auth/AuthModeSync.tsx`.

### F-09 — Mobile source support exists; production UX proof does not (P2)

Safe-area padding, responsive layouts, labelled controls, and horizontal
overflow for timelines/tables are implemented. The Ziwei square grid remains
information-dense on narrow screens. There are no repository browser E2E tests
for the three intake-to-report flows, account sync/delete flow, or mobile
viewport behavior.

Evidence: `src/app/globals.css`, `src/components/form/BirthWizard.tsx`,
`src/components/chart/{BaziTable,DayunTimeline}.tsx`,
`src/components/ziwei/PalaceGrid.tsx`, `package.json`.

### F-10 — Security headers depend on deployment examples (P2)

`next.config.ts` contains standalone output configuration but no application
response-header policy. Nginx/Caddy examples add CSP and related headers, but a
direct deployment, an altered proxy, or a new platform can omit them without a
test detecting it.

Evidence: `next.config.ts`, `deploy/nginx.example.conf`,
`deploy/Caddyfile.example`.

### F-11 — Task and project documents mix historical and current state (P1)

`PROJECT_REVIEW.md` still reports the 2026-07-21 Alpha baseline of 56 test
files / 444 tests and unresolved P0s. `REMEDIATION_TASKS.md` reports 69 / 546,
but marks T253/T262/T271 as done despite the evidence above. The visible Ziwei
sync message is another stale product document. The documents need a single
current-status convention and explicit historical-baseline labels.

Evidence: `docs/PROJECT_REVIEW.md`, `docs/REMEDIATION_TASKS.md`,
`docs/EXECUTION_GUIDE.md`, `src/app/charts/page.tsx`.

### F-12 — Quality and operational gaps remain (P2/P3)

CI runs lint, unit tests, and build but has no API attacker/integration suite,
browser E2E suite, required external-comparison gate, or executed Docker runtime
verification. Lint intentionally permits eight warnings, including two
`aria-required` role violations. Local cold compilation logged a slow-filesystem
warning and required roughly 26.6 seconds for the first health endpoint; this is
an environment signal requiring reproducible investigation, not a confirmed
production regression.

Evidence: `.github/workflows/ci.yml`, `Dockerfile`,
`docs/REMEDIATION_TASKS.md` (T251/T300/T301), lint output recorded above.
